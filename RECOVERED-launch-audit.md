## 1. Closing the window on macOS then reopening from the dock throws on duplicate ipcMain.handle and wedges the app

- **Severity:** launch-blocker · **Category:** crash-or-wedge · **Area:** filesystem-security · **id:** `macos-reopen-wedges-app`
- **Location:** `src/main/index.ts:201`

**Trigger.** On macOS: close the main window (red X or Cmd+W). window-all-closed does not quit on darwin, so the app stays in the dock. Click the dock icon.

**Consequence.** `activate` calls createWindow(), which calls registerAllIPC(mainWindow) at index.ts:102 -- before loadURL/loadFile at 105-110. registerTerminalIPC immediately re-registers 'terminal:create', which Electron 28 throws on. Compounding it, window-all-closed already ran terminalManager.cleanupAll() (index.ts:209-215), so every running agent PTY was killed by the close with no warning -- the close prompt only offers to save the workspace JSON.

**Evidence.** src/main/index.ts:201-205:
```

  if (BrowserWindow.getAllWindows().length === 0) {

  }
});
```
src/main/ipc/index.ts:14-21 calls the register* functions unconditionally, and every one of them uses bare `ipcMain.handle` with no removeHandler (e.g. src/main/ipc/file-ipc.ts:69, terminal-ipc.ts:10). Confirmed the throw is real in the bundled runtime -- `strings` on Electron Framework 28 yields: `Attempted to register a second handler for '${e}'`.

**Fix.** The idempotent-registration approach is right, but the auditor named a method that does not exist. Even with registration made idempotent, the reopened window's close handler at index.ts:119 (`if (closeConfirmed || !rendererReady) return;`) short-circuits forever, so the save-workspace prompt never appears again for the rest of the process lifetime. Reset both to false at the top of createWindow().

## 3. Every keystroke is captured regardless of terminal echo, so passwords typed at a sudo/ssh prompt are written to the workspace JSON in cleartext

- **Severity:** launch-blocker · **Category:** security · **Area:** pty-lifecycle · **id:** `sudo-password-captured-to-disk`
- **Location:** `src/main/terminal/terminal-manager.ts:568`

**Trigger.** In any Cate terminal, run `sudo <anything>` (or `ssh host`, `mysql -p`, a git credential prompt) and type your password at the non-echoing prompt, press Enter. Then save the workspace (Cmd+S, or click Save in the close dialog).

**Consequence.** writeToTerminal buffers printable characters with no awareness of whether the PTY is echoing. The password is flushed on Enter, classified as `shell-command` (a bare one-word token trips no redaction pattern), and emitted as a PromptEntry. The renderer's prompt store hands it back to saveCurrentWorkspace, which writes `promptHistory` verbatim into ~/Library/Application Support/<app>/workspaces/<id>.json. Disk exposure is unconditional. Separately, if the user has configured a Groq API key, renameTerminal fires at promptCount 1 and 3 and ships `promptHistory.slice(-5)` to Groq — redactSensitive matches nothing in a bare password, so a password typed among a terminal's first few lines is sent to a third-party API in plaintext. Same unconditional capture means text typed inside vim/less (e.g. editing a .env) is also harvested into prompt history.

**Evidence.** src/main/terminal/terminal-manager.ts:545-569 — `const cleaned = stripInputEscapeSequences(data); for (...) { ... } else { active.inputBuffer += ch; }` (no echo/termios check anywhere).
src/main/terminal/terminal-manager.ts:582-598 — `const result = processInputBuffer(buffer); if (!result.shouldCapture) return; const entry: PromptEntry = { ... text: result.text, ... }`
src/main/workspace/workspace-service.ts:75 — `promptHistory: workspace.promptHistory,` then `:80 writeFileSync(filePath, JSON.stringify(toSave, null, 2), "utf-8");`
src/main/groq/groq-naming-service.ts:336-338 — `const redactedPrompts = context.recentPrompts.map((p) => redactSensitive(p).slice(0, 300))` — redactSensitive (prompt-capture.ts:142) only matches KEY=value/Bearer/base64 shapes, never a bare secret.

**Fix.** Keep the echo-suppression approach (new `echoSuppressed: boolean` on ActiveTerminal in terminal-types.ts; set in the pty.onData handler when the stripped tail looks like a password prompt; in flushInputBuffer clear inputBuffer and return before building the PromptEntry, resetting the flag on that flush) -- with two corrections. (1) The proposed regex is too narrow: /(password|passphrase)( for [^:]*)?:\s*$/i misses git's `Password for 'https://user@github.com':` (the URL's own colons defeat [^:]*), OpenSSH's `user@host's password:`, and 2FA `Verification code:`. Use something like /(password|passphrase|verification code)[^\n]{0,80}:\s*$/i against the tail of stripInputEscapeSequences(data). (2) Do NOT run PromptEntry.text through redactSensitive wholesale before it reaches the renderer/disk -- its base64 rule /[A-Za-z0-9+\/]{40,}={0,2}/g eats any 40+ char alphanumeric run (long path segments, commit SHAs, ordinary flags), so legitimate Agent Memory entries would silently become [BASE64_REDACTED]. Apply only the KEY=value / Bearer / PRIVATE KEY rules on the disk/UI path and leave the base64 sweep where it already is, on the Groq path. Worth fixing while in here: redact outputPreview in buildUserMessage (groq-naming-service.ts:337-347), which today goes to Groq raw.

## 30. Workspace save is a non-atomic overwrite — a crash or full disk mid-write destroys the whole workspace and it vanishes from the Home list

- **Severity:** medium · **Category:** data-loss · **Area:** workspace-persistence · **id:** `non-atomic-workspace-write`

**Trigger.** Press Ctrl+S (or choose "Save & Close" on quit) on a workspace with a few terminals, sticky notes and prompt history, and have the process die mid-write — power loss, force-quit, OOM kill, or ENOSPC on a full disk. The JSON of a real workspace is tens to hundreds of KB, so the write is not a single atomic block.

**Consequence.** writeFileSync truncates the existing file to zero and then streams the new content in. If it does not complete, the workspace file on disk is a partial JSON document. On next launch listWorkspaces() JSON.parse throws, hits the bare `catch {}` at line 161-164, and the workspace is silently omitted from the Home screen — no error, no entry, no recovery path. loadWorkspace() likewise returns null. The user's entire workspace (layout, groups, notes, file nodes, connections, prompt history) is gone with zero indication that anything happened. There is no backup copy and no .bak/.prev file anywhere in the service.

**Evidence.** src/main/workspace/workspace-service.ts:80  `writeFileSync(filePath, JSON.stringify(toSave, null, 2), "utf-8");`  — direct overwrite of the live path; and src/main/workspace/workspace-service.ts:161-164 `} catch {\n        // Skip corrupted files\n        logger.warn(`Skipping corrupted workspace file: ${filePath}`);\n      }`

**Fix.** Write-then-rename is correct and the tmp name is safe (`x.json.tmp` does not match listWorkspaces' `.endsWith('.json')` filter, so a leftover tmp never shows up as a phantom workspace). Do NOT take the optional `.bak` copy the auditor suggests: it doubles the write volume and introduces its own partial-write window on the copy, for a recovery path nothing in the app can actually surface. Apply the same write-then-rename to renameWorkspace (workspace-service.ts:196), which is the identical read-modify-write onto the live path and is currently the one that runs on a plain click of the rename button.

**Verifier note.** Evidence verified verbatim: workspace-service.ts:80 is a bare `writeFileSync(filePath, ...)` onto the live path, and the `catch {}` at 161-164 in listWorkspaces() does silently drop an unparseable file, so a truncated workspace really does vanish from the Home screen with no error path. No .bak/.tmp anywhere in the service, confirmed by reading the whole file. Two corrections to the auditor's framing. (1) Severity is inflated. The realistic trigger is not 'a crash' generically -- it requires abnormal termination (power loss, OOM, force-quit) or ENOSPC during the write. This is the durability posture of most shipped Electron apps; it is worth fixing because it is cheap, not because it is likely.
