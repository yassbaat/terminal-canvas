## Description

## Multiple terminals are useful. Managing them is not.

Once a project has an agent on the API, another on tests, a dev server, a watcher, and a spare shell, terminal tabs stop being a simple solution. The names look the same, important output gets buried, and it becomes hard to remember which prompt went to which agent.

**Terminal Canvas puts every terminal in one place.** Each session is a clearly labeled card on a visual canvas. Arrange them by project or task, keep notes beside the work, and open the full prompt history for any terminal when you need context.

You can look at the canvas and understand what is running without opening ten tabs one by one.

### What you get

**All your terminals in one view**

These are real PTY terminals using your shell, PATH, and working directory. Move and resize them across the canvas so the layout matches the way you work.

**Clear labels for every session**

Name terminals by task, project, or agent. Terminal Canvas can also suggest session names, so “Shell 7” can become something useful like “API refactor” or “Test runner.”

**Agent Memory for every session**

Terminal Canvas keeps the prompts and commands you submitted, without filling the history with terminal output. Search them, pin the important ones, copy them, or resend a prompt to the same agent.

**Files beside the work**

Open the project file drawer beside a terminal and read code with syntax highlighting. You can also place files directly on the canvas next to the session that is working on them.

**Groups, notes, and connections**

Group related terminals, add notes for decisions and follow-ups, and connect related work. The canvas stays readable even when several agents are running at once.

**Focus Mode**

Move one or more sessions into a clean focus view when you need to read closely or take over manually. Press Escape to return to the full canvas.

**Local-first by default**

Your workspaces are saved locally as JSON. There is no Terminal Canvas account, cloud database, or telemetry. Optional AI naming uses Groq only if you turn it on; the core app works without an API key.

### FAQ

**Is the app code-signed?**  
Not yet. On first launch, macOS may require a one-time approval in System Settings → Privacy & Security → Open Anyway.

**Does it require an AI API key?**  
No. AI-assisted session naming is optional. The core app and offline naming work without one.

**Do my prompts leave my machine?**  
Not by default. Only optional Groq naming sends redacted context, and only after you enable it.

**Is the free build limited?**  
No. The current launch build includes the full app. A separate free and paid model may be introduced in a future version, but this download is not capped.

**How do updates work?**  
Buyers can receive update emails and download replacement builds from their Gumroad Library. Automatic in-app updates are not included yet.
